## 0. 一页版（PPT P2–P4 的内容来源）

**创意名称**：PromptForge（提示词锻造台）
**所属主题**：Coding
**一句话**：把"一句话需求"编译成可验收的方案，让多个模型真实跑一遍，用证据（而不是感觉）告诉你选哪个。

**Demo 要证明的一件事**：同样一句业务需求，两个模型/两种提示策略各写一版 FastAPI 接口；PromptForge 真实跑 6 条 pytest，用通过率、失败用例、耗时、token 费用和评委分做决策，并给出可解释的推荐——**不是"AI 说它更好"，而是"6 条验收用例里它过了几条"**。

**最小闭环（只做这一条链路）**：

```text
一句话业务需求（FastAPI 待办 API：标签筛选 + 分页）
  → 需求编译：SRD（目标 + 约束 + 6 条可执行验收标准）
  → 2 份候选提示词（假设不同：直接改实现 / 先列边界条件再实现）
  → 2 个模型（glm-5.2 / openpangu-2.0-flash）各生成一份 app/main.py
  → 沙箱执行：pytest + 计时（6 条验收用例）
  → 证据包 Evidence Packet（测试红绿、失败用例、耗时、token 费用）
  → 规则评审 + 1 个 LLM 评委盲评
  → 决策卡：推荐方案 + 证据链 + 次优备选 + 成本
```

**不做什么（Demo v0.1）**：不做融合、不做多轮迭代、不做完整 Web 工作台、不接 WorkSwarm 集群（放 Demo v0.2/S6）、不做多模态。

## 1. 场景与输入（选一个"有硬证据"的 Coding 任务）

**场景（已确认）**：给已有的 FastAPI 待办 API 加"标签筛选 + 分页"。

| 项 | 内容 |
|---|---|
| 用户输入（一句话） | "给待办列表接口加标签筛选和分页，支持 limit/offset，返回 total。" |
| 任务载体 | 已有 `repo/app/main.py`（FastAPI + 内存存储，只有 POST /todos 和 GET /todos 全量列表） + `repo/tests/test_tags_pagination.py`（6 条验收用例，预先冻结） |
| 为什么选它 | 业务真实（列表接口的筛选/分页是高频需求）、代码量小、运行快（秒级）、边界清晰（tag/limit/offset/空结果/非法参数），最容易在 60 秒里讲清"证据差异" |
| 备选 | 给待办 API 加"截止日期排序 + 导出 CSV"；或修一个真实 bug（需另备仓库） |

**SRD 验收标准（6 条，全部可执行）**

| ID | 验收标准 | 测试方式 |
|---|---|---|
| A1 | 默认响应结构为 `{items, total, limit, offset}`；无参数时 limit=20、offset=0 | 创建 3 条数据（带唯一 tag），GET `/todos?tag=a1` 检查结构与计数 |
| A2 | `tag` 过滤：只返回 tags 中包含该标签的记录 | 构造不同标签数据，GET `?tag=a2x` |
| A3 | 分页：`limit`/`offset` 生效，`total` 是过滤后的总数 | 创建 5 条，GET `?tag=a3&limit=2&offset=2` |
| A4 | 组合：`tag` + `limit` + `offset` 同时生效，顺序正确 | 创建 4+2 条，GET `?tag=a4&limit=2&offset=1` |
| A5 | 空结果：tag 无匹配时 200 + `items=[]、total=0` | GET `?tag=a5-none` |
| A6 | 非法参数：`limit=0/101`、`offset=-1` 返回 422 | 三个请求逐一检查 |

| 候选 | 生成模型 | 提示策略（假设） | 预期演示剧情（**待实测**） |

| A | glm-5.2 | "直接改 GET /todos 实现标签筛选和分页" | 可能通过 A1/A2/A3/A5，但漏掉 A4 组合与 A6 参数校验 → 4/6 |

## 3. 证据与决策（Demo v0.1 的硬规则）

**证据包字段（第一版）**

```json
{
  "candidate": "A",
  "tests": {"passed": null, "total": 6, "failed_cases": []},
  "runtime_ms": null,
  "cost": {"tokens_in": null, "tokens_out": null, "cny": null},
  "judge": {"model": "TBD", "scores": {"correctness": null, "completeness": null, "maintainability": null}},
  "reproducible": {"task_set_version": "v0.1", "python": "3.11", "date": "TBD"}
}
```

**决策规则（先硬后软）**

1. **硬约束**：测试未全过的候选不能当推荐（可作"次优/观察"展示）；
2. **规则评审**：通过率、失败用例数、耗时、费用；
3. **LLM 评委**：另 1 个模型按 3 维 rubric 盲评（1–5 分），只做解释与同分裁决；
4. **决策卡**：推荐 + 证据引用 + 次优备选 + 成本 + 置信说明（v0.1 不做统计显著性，明说"样本少，结论仅用于演示"）。

**Demo 成功判据（DoD）**

- [ ] 一条命令跑通：输入需求 → 生成 2 份实现 → 真实执行 6 条测试 → 输出 `evidence.json` + `decision.md`；
- [ ] 本地总耗时 ≤90 秒（不含模型排队；超时则缓存回放）；
- [ ] 至少一条"候选失败"的测试被真实展示（红/绿对比）；
- [ ] 费用字段来自真实 token 统计（可含价格快照），不能手填；
- [ ] 录屏 60 秒，画面里能看到命令执行与测试输出；
- [ ] 断网可回放：缓存证据 + 录屏兜底。

## 4. 分镜：60 秒创意版 / 3 分钟 DEMO 版

### 4.1 60 秒创意版（11-10 前，用于创意 PPT）

| 时间 | 画面 | 台词/字幕 |
|---|---|---|
| 0–5s | 黑底白字 / 一句话 | "AI 写的接口，你敢直接合并吗？" |
| 5–15s | CLI 输入需求 | "给待办列表接口加标签筛选和分页，支持 limit/offset，返回 total。" |
| 15–30s | SRD 6 条验收 + 两候选并行生成 | "系统先把需求变成 6 条可执行验收标准，再让两个模型各写一版。" |
| 30–45s | 真跑 pytest：A 红、B 绿 | "A 过了 4 条，组合查询和参数校验没过；B 过了 6 条。" |
| 45–55s | 决策卡 | "推荐 B，理由都指得到测试输出；成本/耗时见账单。" |
| 55–60s | Slogan | "PromptForge：一次选对，少返工。" |

### 4.2 3 分钟 DEMO 版（12-27）

| 时间 | 内容 |
|---|---|
| 0:00–0:20 | 问题：提示词质量方差大、单模型自评不可靠、接口返工贵 |
| 0:20–0:50 | 输入需求 + 需求编译器回显 SRD（6 条验收标准） |
| 0:50–1:40 | 两候选并行生成；沙箱执行；测试红绿实时滚动 |
| 1:40–2:20 | 证据对比：失败用例、耗时、token 费用、评委分 |
| 2:20–2:45 | 决策卡：推荐 + 证据链 + 次优备选 + 成本账单 |
| 2:45–3:00 | 可复现与扩展：证据包可回放；下一步接 WorkSwarm 集群 |

> 拍摄要点：不剪掉"候选 A 失败"的画面；失败用例名要出现在屏幕上；费用数字必须来自真实 token 统计。

## 6. 风险与兜底

| 风险 | 影响 | 兜底 |
|---|---|---|
| 模型 API 不稳定/限流 | 演示卡住 | 缓存上一次真实结果回放；备用模型 |
| 生成代码质量过低（0/6） | 演示效果差 | 更换提示策略；保留"失败也是证据"的叙事 |
| 测试环境差异 | 执行失败 | 固定 `requirements.txt` + venv；CI 自检 |
| 现场网络断 | 无法调用模型 | 本地录屏 + 证据回放，不假装实时 |
| 数据/合规 | 评审风险 | 仅官方 API/本地部署；演示数据脱敏；不伪造测试结果 |
